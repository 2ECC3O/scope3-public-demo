# Practical evaluation: EPA facility gas-total arithmetic

Predeclared 20 September 2026, before reading detector outcomes.

Source: EPA GHGRP 2023 data summary archive, `ghgp_data_2023.xlsx`, `Direct Point Emitters`, as reported to EPA on 16 August 2024. Source archive URL: https://www.epa.gov/system/files/other-files/2024-10/2023_data_summary_spreadsheets.zip . Archive SHA-256: 895349c8008b7962dba68659c8187cec6b340d68be84ccb3f0e7fb6037bf8345. The source reports metric tonnes CO2e using AR4. This is public direct-emissions data, not Scope 3 supplier data.

Evaluation contract: map the reported total and gas-level CO2e components in their original units to step 2's existing shared exact-identity checker; do not create product, supplier, monthly, or other Scope 3 columns. Retain only facilities with numeric positive total, numeric nonnegative CO2/CH4/N2O, and no populated additional gas field. Treat blanks in other gas fields as not reported, not proven zero. Report excluded rows. Before scoring, choose the first 24 eligible even-ID rows as development and first 24 eligible odd-ID rows as held-out evaluation, in workbook order. Do not look at held-out detector outcomes or change this rule after development.

For each split, inspect authentic rows unchanged, then make a separate copy with deterministic total-field errors: multiply the total by ten in rows at positions 3 and 11 (one-based). Check original total against the independently recomputed sum to establish only whether arithmetic holds; do not claim EPA values are otherwise true. A positive controlled error is a changed total cell, and a negative is an unchanged total cell. Report TP/FP/FN/TN and denominators on the controlled copy. The checker must receive all rows at once so its cohort threshold behaves as designed. Recheck source selection and arithmetic assertions before running the checker. Development run precedes held-out run. No tuning on held-out answers.

Limits: this tests a single cross-field identity function on a narrow public dataset. It does not test the full fixed-schema verifier, ingestion, field mapping, physical plausibility, customer usability, or Scope 3 accuracy. Full-schema absent fields remain unverified. The raw archive and extracted workbook stay ignored under `output/practical-evaluation/`; the runnable script re-fetches nothing and accepts a local workbook path.

## Executed result (20 September 2026)

The declared protocol was run against the exact downloaded archive and extracted workbook above. The adapter is `tools/practical_evaluation.py`. It calls the existing step-2 `_check_identity_violation` function; there is no copied detection algorithm and no change to pipeline code. The input is 2023 EPA direct-emitter facility data. All four compared fields are already metric tonnes CO2e under AR4; no new global-warming-potential multiplication occurs. Among the first 64 candidate workbook rows, 16 did not meet the declared eligibility rule and 48 were selected, split by facility ID parity into 24 development and 24 untouched evaluation facilities. EPA's workbook does not explicitly define a blank other-gas cell as zero, so the test treats the three available gas fields as a *reported-component consistency comparison* and makes no claim that the total's full gas coverage is independently proven.

On the unchanged source rows, all 48 reported totals agreed with the three reported component sums within the predeclared independent check (absolute 0.001 tonnes CO2e or relative 1e-8). This is arithmetic consistency in EPA's published table, not proof that the underlying emissions were measured correctly. Deliberately changed copies multiplied two total cells by ten in each split. The development pass raised two row reviews for two changed totals, and none for 22 unchanged totals: TP 2, FP 0, FN 0, TN 22. The held-out evaluation pass repeated TP 2, FP 0, FN 0, TN 22. Thus controlled-error detection was 2/2 in each split; false review count was 0/22 in each. The checker deliberately did **not** name the total cell as faulty, because these facilities lack the product baseline it uses for attribution. Its output is a row review, not a correction or a verified cell-level diagnosis. The two splits are tiny and the ×10 corruptions large, so this is a smoke test of one arithmetic rule, not a general performance estimate.

The full verifier cannot run against this source because EPA reports facilities annually and does not supply the project's required product, supplier, monthly material/waste, or Scope 3 fields. Those absent fields remain **UNVERIFIED**. This workflow makes one existing check practically runnable on outside data while exposing the remaining ingestion and coverage boundary. The source archive and extracted workbook remain outside Git under ignored `output/practical-evaluation/`; use the official URL above and the recorded SHA-256 to reproduce. EPA's general data policy says EPA-produced data are public domain unless otherwise specified, but this raw EPA workbook is excluded from the release package pending exact-file redistribution review.

## Preserved review artifacts and development checks

The original executed v1 figures above remain unchanged. A later documentation and provenance pass did **not** change the source selection, split, corruption positions, detector, or scores. The final runnable adapter rejects a workbook whose SHA-256 differs from `e348830722f59de38640b6f3ddfc9b7d406f26c3c153ffbdd7192c2260114ac3`, verifies the EPA year, reporting date, units and gas headers, and closes the workbook. It rejects missing/nonfinite values and refuses to label source rows as clean if the reported-component sum already disagrees with the source total. The source header and row values alone are insufficient to identify the pinned EPA file; the hash provides that identity.

Final ignored output: `output/practical-evaluation/review-v3/summary.json`, `facility_reviews.csv`, and `PASS.json`. The JSON records 24 development and 24 evaluation facility IDs, source/checker/adapter SHA-256 values, selection and four score blocks. The CSV has 96 rows: 48 untouched source rows and 48 separate controlled copies, with reported values, three-component sum, residual, injected flag and actual row-review status. The pass manifest hashes both files. Runs require a fresh `--output-dir`; existing evidence is never overwritten. The unchanged EPA rows produced 0/24 row reviews in each split. The controlled-copy v1 scores remain 2/0/0/22 in each split (TP/FP/FN/TN). This proves only the selected rows' reported-component arithmetic and controlled-error behavior; the EPA workbook does not establish that blank other-gas cells are zeros.

Four development-only regression checks passed. The adapter rejects missing, Boolean and nonfinite input; pre-existing source arithmetic disagreement is not silently counted as a clean negative; a tiny rounding difference raises no review; and an equal change to a total and one gas component leaves the identity balanced and therefore invisible. These are boundary checks, **not** additional held-out benchmark cases. No verifier algorithm was changed or shown to improve.
